# Contributing to oneyaml

Thank you for helping. Bug reports, failing inputs, documentation fixes
and code are all welcome.

## Before you start

- **Found a bug?** Open an issue with the
  [bug report form](https://github.com/recursive-ai-oss/oneyaml-rust/issues/new/choose).
  The input that shows it, and what you expected, are the most useful
  parts.
- **Found a security issue?** Don't open an issue; follow
  [SECURITY.md](SECURITY.md).
- **Want to change behaviour or add an API?** Open an issue first, so
  the design can be agreed before you write code. Some things are out of
  scope by design (see
  [When not to use oneyaml](https://github.com/recursive-ai-oss/oneyaml-rust/blob/main/crates/oneyaml/README.md#when-not-to-use-oneyaml)),
  and any departure from YAML 1.2 can only be an opt-in, named setting
  that is off by default.

## Set up

You need a recent stable Rust and `git`. The published crates build with
Rust 1.85 (the MSRV); the test and benchmark tooling (`oracles`, `bench`,
`fuzz`) depends on other YAML libraries that need a newer compiler.
Clone the repository; everything else comes from Cargo.

```sh
git clone https://github.com/recursive-ai-oss/oneyaml-rust
cd oneyaml-rust
cargo test -p oneyaml
```

The workspace has three published crates (`oneyaml-core` ←
`oneyaml-syntax` ← `oneyaml`) and unpublished tooling: `test-suite` (the
vendored yaml-test-suite and its runner), `oracles` (the other YAML
libraries we compare against, used only in tests), `bench` and `fuzz`.

## Test

```sh
cargo test --workspace                     # everything, including the yaml-test-suite and doc tests
cargo test -p oneyaml --doc                # the README and rustdoc examples
cargo test -p oracles --doc                # the migration guide's examples
cargo run -p test-suite -- --producer parser   # strict yaml-test-suite run
cargo test -p fuzz                         # replay the fuzz corpora (no fuzzer needed)
```

Fuzzing itself is described in [crates/fuzz/README.md](crates/fuzz/README.md).

## Reproduce the benchmarks and conformance numbers

The benchmark tables in [docs/performance.md](docs/performance.md) and
the crate README are generated by the `bench` tool; the commands, and
what they need (valgrind, a quiet machine), are in
[Regenerate](docs/performance.md#regenerate). The yaml-test-suite
numbers in [docs/conformance.md](docs/conformance.md) come from the
`oracles` crate; that page says how to re-run them.

## Lint and format

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
RUSTDOCFLAGS='-D warnings' cargo doc --no-deps -p oneyaml -p oneyaml-core -p oneyaml-syntax
```

The workspace lints forbid `unsafe` and deny `unwrap`, `expect`,
`panic!`, slice indexing and unchecked arithmetic in library code.

## Pull requests

A pull request is easier to review when it:

- does one thing, and links the issue it relates to;
- adds a test that fails without the change; a bug fix adds the input
  that showed the bug;
- explains any change to golden output files, corpora or benchmark
  baselines (the default output bytes don't change within a major
  version, except to fix incorrect output);
- adds an entry to [CHANGELOG.md](CHANGELOG.md), flagging any breaking
  change;
- adds no runtime dependency without discussing it in an issue first,
  and no `unsafe` or panicking path;
- explains any instruction-count or allocation regression it causes.

The [pull request template](.github/PULL_REQUEST_TEMPLATE.md) lists the
same points.

## Minimum supported Rust version

The published crates support Rust 1.85. Don't use a language or library
feature newer than that in them; check with
`cargo +1.85 check --workspace --exclude oracles --exclude bench --exclude fuzz --all-targets --all-features`. The MSRV policy is in the
[crate README](https://github.com/recursive-ai-oss/oneyaml-rust/blob/main/crates/oneyaml/README.md#minimum-supported-rust-version).

## Style

- `cargo fmt` formatting; comments and docs in plain English, second
  person for user docs.
- Every public item has a doc comment with an example, and `# Errors`
  for anything that returns `Result`. Examples use `?`, not `unwrap()`.
- New diagnostics get a new `Y####` code; a code's meaning never
  changes.

## Documentation

The crate README is also the docs.rs front page, so every `rust` code
block in it is a doc test, and links in it must be absolute URLs. Tables
between `<!-- bench:…:begin -->` and `<!-- bench:…:end -->` markers are
generated by the `bench` tool; don't edit them by hand.

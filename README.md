# oneyaml

**serde and lossless, comment-preserving editing for YAML 1.2, in one
crate.** Both run on one parser and one interpretation of the file, so a
typed read and an edit never disagree about what it means. Correct by
default, no `unsafe`, no panics on any input.

## Why oneyaml

- **One parser, one meaning.** serde and the lossless `Document` read
  the same events through the same resolver, so a typed read and an edit
  never disagree about what a file means.
- **Edits that keep your file.** An untouched document writes back byte
  for byte; an edit changes only what you touch, and every comment stays
  with the entry it belongs to, also when you move the entry
  ([comment rules](docs/comment-attachment.md)). JSON Patch and merge
  patches change values the same way, all or nothing (a patch `move`
  carries the value without its comments)
  ([patches](crates/oneyaml/README.md#patches-and-pointers)).
- **Correct YAML 1.2.2 by default.** `yes` is a string and `0777` a
  decimal integer; every YAML 1.1 behaviour, `<<` merge keys included,
  is a named setting, off by default. Checked against the full
  yaml-test-suite ([conformance results](docs/conformance.md)).
- **Safe on any input.** No `unsafe`, no panics, resource limits on
  every read and a `Limits::untrusted()` profile for network input;
  fuzzed ([crates/fuzz](crates/fuzz/README.md)) and tested against five
  other YAML libraries.
- **Fast, with the losses shown.** Fewer instructions than each
  competitor on most workloads in the chart above. Not everywhere: a
  typed read of the OpenAPI workload and edits of the smallest file take
  more instructions, and in wall-clock time typed reads are slower on
  most of these workloads, `Document` parsing is level or slightly slower
  on some, and yaml-edit edits small files faster
  ([every loss](docs/performance.md#results-at-a-glance)).

More in the [crate README](crates/oneyaml/README.md#why-oneyaml), and
[how oneyaml compares](docs/comparison.md) with the other YAML crates,
including where they win.

## Install

```sh
cargo add oneyaml serde -F serde/derive
```

## Quick start

Read and write typed data with serde, then edit a document in place:
the edit changes only what you touched, and the comment stays.

```rust
use oneyaml::Document;
use serde::{Deserialize, Serialize};

#[derive(Deserialize, Serialize)]
struct Config { name: String, port: u16 }

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // serde: read and write typed data.
    let cfg: Config = oneyaml::from_str("name: web\nport: 8080\n")?;
    assert_eq!(oneyaml::to_string(&cfg)?, "name: web\nport: 8080\n");

    // Read values from a document.
    let mut doc = Document::parse("server:\n  port: 8080  # public\ntags: [web]\n")?;
    assert_eq!(doc.get_path("server.port").and_then(|n| n.as_u64()), Some(8080));

    // Edit it: everything else, comments included, stays byte for byte.
    doc.set_path("server.port", 9090)?;
    doc.get_mut("tags")?.push("api")?;
    assert_eq!(doc.to_string(), "server:\n  port: 9090  # public\ntags: [web, api]\n");
    Ok(())
}
```

Errors come with a `Y####` code, a source snippet and a suggested fix;
see [diagnostics](crates/oneyaml/README.md#diagnostics). For input from
the network, use [`Limits::untrusted()`](crates/oneyaml/README.md#untrusted-input);
for docker-compose-style `<<` merge keys, turn on
[`merge_keys`](crates/oneyaml/README.md#merge-keys-).
